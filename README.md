# AI Game Save Recovery Playbook

[English](README_EN.md) | 简体中文

**让 AI 帮你找回被覆盖或损坏的单机游戏存档——靠证据恢复，不靠猜。**

> Preserve first. Reconstruct the timeline. Test candidates safely. Write only with approval.

一套让本地 AI Agent 协助处理单机游戏存档覆盖、损坏、版本冲突和配置故障的方法，而不是另一个存档管理器。

> 核心原则：先保护现场，再建立时间线；先证明候选版本，再执行可逆恢复。

## 30 秒理解这个想法

云存档覆盖后，很多人会反复启动游戏、切换云同步、到处复制文件，结果让残留版本继续被覆盖。更安全的做法是：

1. 立刻退出游戏和启动器；
2. 让本地 AI 只读盘点存档、轮换副本、索引和同步日志；
3. 把“哪台电脑、什么时间、上传还是下载、哪个候选版本”还原成时间线；
4. 先保全和验证，再在玩家明确批准后做最小替换。

真正的新意不是某条复杂命令，而是把 AI 当作事故后的调查员和操作协调者，而不是让它直接充当存档修改器。

## 为什么存在

现有开源项目大多解决“以后如何自动备份”，但玩家通常是在事故已经发生后才来求助。此时真正的问题不是缺少一个“恢复”按钮，而是：

- 存档究竟散落在哪些本地目录、云同步缓存和游戏自有备份中？
- 哪个文件代表事故前最后一次有效退出，而不只是修改时间最新？
- 云端、本机和另一台电脑之间发生了什么覆盖关系？
- 如何在不继续破坏证据的情况下验证和恢复？

本项目把 AI 的优势放在搜索、归类、日志阅读、格式识别和证据关联上；最终写入仍然需要玩家确认并保留回滚点。

## 适用范围

- 被 Steam Cloud 或其他同步工具覆盖的本地存档
- 游戏崩溃、升级或 Mod 变更后出现的存档损坏
- 游戏保留了轮换副本、索引文件、日志或临时文件，但缺少恢复界面
- 配置错误、角色/世界槽位错配，以及可由本地证据定位的单机故障
- 玩家明确希望回到某一时间点，并能在游戏内人工验证结果

## 不适用范围

- 联机排行榜、竞技、交易市场、反作弊保护或在线经济
- 未经授权读取他人的电脑、账号、共享世界或存档
- 绕过 DRM、访问控制、加密、数字签名或付费内容
- 修改服务器端权威数据，或伪造在线成就和记录
- 没有备份且写入可能导致证据永久丢失的盲目试错

即使游戏通常被称为“单机”，只要结果会同步到共享服务器、排行榜、他人世界或在线经济，就不应按本方法直接修改。

## 六阶段协议

1. **冻结**：退出游戏和启动器，暂停同步，不启动清理、修复或存档编辑工具。
2. **快照**：复制当前存档、缓存、索引和相关日志，生成文件清单与哈希。
3. **发现**：在明确范围内查找游戏目录、用户数据、启动器缓存和游戏自有备份。
4. **重建**：把用户记忆、会话日志、同步日志、文件时间、索引关系和内容特征组合成时间线。
5. **验证**：复制候选版本到隔离目录；能只读解析就先解析，不能解析时再用离线游戏实例人工验证。
6. **恢复**：恢复前再次备份现状，只替换最小文件集合；验证成功后再决定是否重新启用云同步。

完整说明见 [恢复协议](docs/protocol.md)，可直接复制给 AI 的任务模板见 [Agent 任务模板](templates/agent-task.md)。

## 证据不是同等可靠

推荐的优先顺序是：

1. 游戏内可重复验证的角色、世界或任务状态
2. 游戏或启动器明确记录的退出、上传、下载和版本事件
3. 存档内部元数据及槽位/索引关系
4. 文件哈希、大小、修改时间和轮换序号
5. 用户对时间、等级或事件的记忆
6. 仅凭文件名或“最新文件”作出的猜测

AI 应报告“证据支持到什么程度”，而不是把概率判断写成事实。

## 真实案例

[《雾锁王国》Steam Cloud 覆盖恢复案例](cases/enshrouded-cloud-overwrite.md)来自一次真实恢复，但已经移除 Steam ID、用户名、原始路径、存档文件、IP、哈希和可识别日志。它用于展示方法，不是针对特定版本的永久游戏攻略。

## 与现有工具的关系

本项目不替代 Ludusavi、OpenSave 或其他备份软件。它处理的是事故后的调查与决策层；已有工具可以在恢复完成后承担预防性版本备份。候选上游及不直接提交 PR 的原因见 [上游评估](docs/upstream-assessment.md)。

## 隐私与安全

- 默认只扫描已确认与目标游戏相关的目录，不把“全盘扫描”作为第一步。
- 原始存档、日志和快照默认不进入仓库，也不上传到第三方模型。
- 发布案例必须删除账号 ID、本机用户名、绝对路径、IP、令牌和稳定文件指纹。
- AI 生成的脚本先以只读或预览模式运行；任何覆盖、删除、改名、同步操作均需单独确认。
