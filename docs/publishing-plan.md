## Launch presentation

- Keep the English one-sentence promise and the four-step explanation above the fold.
- Keep both English and Chinese entry points.
- Enable Discussions for recovery reports, failed cases, and method questions.
- Create a first release only after at least one clean public snapshot is verified; do not attach real logs or saves.
- Consider a simple social-preview image later, but do not delay the initial documentation release for branding.

## Promotion boundaries

Allowed and useful:

- Add accurate GitHub topics and a project-related repository description.
- Share the repository in communities where recovery/help posts are permitted and the post directly answers the discussion.
- Mention it in a relevant upstream Discussion or Issue only when it contributes concrete diagnostic value and follows that project's rules.
- Ask for reproducible, de-identified cases rather than stars or follows.

Avoid:

- Posting the same promotional message across unrelated Issues or Discussions.
- Creating Issues in upstream repositories solely to advertise this project.
- Automated starring, following, comments, or engagement exchanges.
- Describing the playbook as an official Steam, Valve, Enshrouded, or Codex recovery tool.
- Claiming guaranteed recovery, universal compatibility, or security validation.
