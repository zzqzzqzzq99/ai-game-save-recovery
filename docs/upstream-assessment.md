# 上游项目评估

评估日期：2026-09-02。结论针对本项目“事故后 AI 取证与恢复方法”，不评价下列工具的一般质量。

| 候选 | 已有能力 | 与本方法的缺口 | PR 判断 |
|---|---|---|---|
| [SteamCloudFileManager](https://github.com/Fldicoahkiin/SteamCloudFileManager) | 解析 Steam 云文件元数据、查看和管理云存档；路线图包含冲突处理、云备份和版本历史 | 主要是 Steam Cloud 文件管理器，不负责跨目录取证、用户目标重建和游戏内验证 | 最接近，但适合先提“导出诊断包/冲突时间线”的 Issue；直接加入 AI 工作流会扩大产品边界 |
| [Ludusavi](https://github.com/mtkennerly/ludusavi) | 成熟的跨平台存档发现、备份、恢复、云同步和 CLI | 以已知路径和已有备份为中心，不是事故后的通用证据调查器 | 可贡献新游戏路径或确定性功能；不适合提交宽泛 AI 方法 PR |
| [Game Save Manager](https://github.com/dyang886/Game-Save-Manager) | 自动发现、版本备份、历史恢复和跨设备迁移 | 重点是预防性快照；事故前没有使用它时，无法替代残留证据重建 | 可提交具体恢复功能，但当前方法不是其单一功能补丁 |
| [OpenSave](https://github.com/Liquid-co/OpenSave) | 不可变快照、分支和冲突解析 | 解决使用工具后的安全同步，不覆盖事故前未纳管文件的调查 | 方法可借鉴，但没有自然的 PR 落点 |
| [SaveState](https://github.com/Matteo842/SaveState) | 智能路径发现、备份与恢复 | README 明确表示不接受代码 PR | 不作为 PR 目标；可在合适时提交 Issue/反馈 |

## 结论

当前没有一个上游同时满足：

1. 接受外部贡献；
2. 职责覆盖事故后的文件与日志取证；
3. 愿意引入 AI Agent 执行协议；
4. 能容纳跨游戏、跨启动器且以人工确认收口的方法。

因此，不应为了“有一个 PR”而把方法硬塞进备份工具。更好的路线是：

- 本仓库维护通用、工具无关的方法和脱敏案例；
- 将来发现可确定实现的小能力时，再向上游提交窄 PR；
- 最值得先验证的上游贡献，是为 SteamCloudFileManager 增加**只读诊断导出**：按 AppID 导出脱敏后的相关日志事件、缓存元数据、文件清单与哈希，但不让 AI 或工具自动选择并覆盖存档；
- 在写代码前先向维护者提 Issue，确认诊断导出的数据模型、隐私范围和是否接受贡献。

这使上游工具保持确定性，也让 AI 方法可以独立演进。
